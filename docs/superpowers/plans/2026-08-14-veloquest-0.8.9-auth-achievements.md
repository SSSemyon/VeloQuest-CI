# VeloQuest 0.8.9 Auth and Achievements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Ship VeloQuest 0.8.9 with Google PKCE auth, a replay-safe VK ID backend bridge, future Apple identity compatibility, and server-authoritative achievements with cosmetic rewards and small one-time XP bonuses.

**Architecture:** Authentication is split into a client PKCE orchestrator, Supabase-native Google identity, and three server-only VK bridge functions backed by private one-time transaction records. Achievements are evaluated from canonical Ride events inside an idempotent database transaction; definitions are versioned, unlocks are immutable, rewards use unique keys, and XP continues through the existing ledger.

**Tech Stack:** Expo 57, React Native 0.86, TypeScript 6, Supabase JS 2.112.1, Supabase Auth/PostgreSQL 17/Edge Functions, Node test runner, pgTAP, Xcode Personal Team.

## Global Constraints

- Base exactly 208a4964f12b3c13271687ed1e4199a5025c5fc0.
- Work only on agent/auth-achievements-0.8.9.
- Preserve all 0.8.8 email/password, recovery, session, Ride, XP, quest, H3, privacy, Garage, and catalog contracts.
- Google uses Supabase OAuth with PKCE and veloquest://auth/callback.
- VK secrets and code exchange stay only on the backend.
- Apple is schema-compatible but absent from the UI.
- No client may write XP, achievement progress, unlocks, or reward grants.
- No reward for duplicate, manual/historical GPX/FIT, GPS spikes, or max speed.
- Real Bike and VeloQuest Bike remain separate; cosmetics are never real components.
- Production remains unchanged until the complete preflight is green.
- 0.8.9 uses iOS build 9 and Android versionCode 9.
- Physical-device E2E is not complete until real iPhone, iPad, Android phone, and Android tablet checks are recorded.
