# VeloQuest 0.8.7 Device Candidate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a verified VeloQuest 0.8.7 Xcode-installable device candidate with evidence-backed Hagen catalog coverage and no regression of the production/security contracts.

**Architecture:** Extend the existing generated SQL catalog pipeline with a dedicated Hagen evidence manifest and idempotent forward migration. Keep mobile behavior and backend authority boundaries unchanged, add regression contracts before any behavior change, generate the native iOS project from app configuration, and package a source-only deliverable with explicit release evidence.

**Tech Stack:** Expo SDK 57, React Native 0.86, TypeScript 6, Node test runner, Supabase/Postgres migrations and Edge Functions, Xcode/CocoaPods generated by Expo prebuild.

## Global Constraints

- Source baseline is the verified 0.8.6 archive with SHA-256 `272baa104cf432902a0dadd6737aa21c167959e8d621854afdc7c44e666be3c7`.
- Production remains immutable until BE-02 and BE-03 are green.
- Server-authoritative XP, quest, H3, canonical ride, privacy masking, duplicate reward protection, and historical/manual GPX/FIT zero-reward behavior are mandatory.
- Hagen entries require official manufacturer evidence; guessed fields and guessed compatibility equal zero.
- Catalog years are 2020–2026 inclusive.
- Figma and UI redesign are excluded.
- Final source archive excludes secrets, `node_modules`, Pods, native build output, DerivedData, `.expo`, and `.env*`.
