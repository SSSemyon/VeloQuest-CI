# VeloQuest 0.8.7 Device Candidate — Design

## Goal

Produce a fresh, reproducible VeloQuest 0.8.7 source package that opens in Xcode, can be signed with an Apple Personal Team, and is suitable for full physical-device QA. Preserve the 0.8.6 product/security contracts and add every Hagen model-year identity from 2020 onward that can be proven from Hagen's official current or archived material.

## Release truth

- `0.8.7 Device Candidate` means source, generated iOS project, native configuration, static/backend contracts, and export checks have passed.
- It does not mean `Production GO` or physical-device E2E has passed. Those statuses require their own runtime evidence.
- No production database or Edge Function mutation is allowed before backup/rollback, two clean resets, DB/RLS/reward-trust smoke, and the exact migration dry-run sequence are green.
- Figma and visual redesign are outside this release. The current 0.8.6 UI is retained so a later Figma-derived update can be applied without mixing concerns.

## Scope

### Mobile and Xcode

- Keep Expo SDK 57 / React Native 0.86 and the existing bundle identifier `com.semyonsemenyuk.veloquest`.
- Increment application version/build metadata to 0.8.7 / build 7.
- Generate a clean native `ios/` project with HealthKit entitlement, `veloquest://` deep-link scheme, iPhone/iPad portrait support, and required privacy strings.
- Include deterministic Mac/Xcode installation instructions for dependency install, CocoaPods, Personal Team selection, device trust, and launch.
- Do not embed credentials, signing identities, build output, `node_modules`, Pods, or user-specific Xcode data in the release archive.

### Functional fixes

- First reproduce defects through automated tests or a deterministic diagnostic.
- Fix only confirmed P0/P1 defects that affect the required MVP paths.
- Preserve server-authoritative XP, quest, H3, canonical ride, privacy masking, duplicate reward protection, and historical/manual GPX/FIT zero-reward behavior.
- No client-side fallback may fabricate successful server functionality while production is on HOLD.

### Hagen catalog

- Scope is all distinct Hagen bicycle model-year identities from 2020 through 2026 that are evidenced by official Hagen pages or official Hagen archive material. If the brand has no official evidence for a year/model, no row is invented.
- Cover every official family: MTB, Women, Gravel, Hybrid, Teen Pro, and Teen.
- A model-year identity is catalog breadth. Specifications, media, components, fitments, compatibility, and recommendations are added only field-by-field when official evidence explicitly supports them.
- Manufacturer pages are the primary evidence. Dealer pages may be recorded as corroboration but cannot override the manufacturer.
- Color and frame-size variants remain variants of one model-year identity unless Hagen assigns separate model names.
- Unknown compatibility remains default deny; factory fitment does not automatically become an upgrade recommendation.

## Data flow

1. Collect official Hagen family, series, and product URLs into a deterministic evidence manifest.
2. Normalize model name, model year, category, region, and source URL.
3. Reject duplicates and unsupported years before generating SQL.
4. Generate an idempotent forward catalog migration; do not edit historical migrations already represented in production history.
5. Run catalog integrity, strict Garage audit, migration reproducibility, and release contract tests.
6. Generate the clean iOS project from the verified source state and run native configuration assertions.

## Error handling and trust

- Missing official fields remain absent, not guessed.
- Source conflicts are quarantined for later review rather than silently selected.
- A catalog ingestion failure must leave the prior catalog intact through idempotent upserts and transaction-safe SQL.
- Network/server failures remain visible to the user as degraded/error states; they are never converted to local XP or quest progress.

## Verification gates

- Full TypeScript and Node test suite: zero failures.
- Edge Function typecheck, SQL parser/build check, backend reproducibility audit, catalog integrity, strict Garage audit, and enrichment queue validation: pass.
- Fresh iOS JavaScript export and clean iOS prebuild: pass.
- Generated project assertions: bundle ID, build number, URL scheme, HealthKit entitlement, privacy descriptions, iPhone/iPad targets.
- Archive inspection: no secrets, `node_modules`, Pods, derived data, build products, or environment files; ZIP integrity and SHA-256 recorded.
- Production and physical-device gates remain separately reported until actually executed.

- Release notes with exact passed/blocked gates.
- Hagen evidence manifest and coverage report.
- Xcode installation and physical-device QA checklist.
- Updated Notion tasks, Current State, and Iteration Archive checkpoint.
