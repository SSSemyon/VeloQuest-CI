# VeloQuest Mobile Alpha 0.8.2 RC

Release candidate prepared after the full functionality, account-isolation,
quest-persistence, anti-abuse and Garage/catalog audit on 2026-08-11.

## Closed release blockers

- Account-scoped runtime/cache isolation and one-owner legacy migration.
- Server-enforced historical handling for GPX/FIT files without trustworthy timestamps.
- Server-authoritative active quest selection, cross-device persistence and partial-progress UI.
- Real Garage parts no longer use game-level locks.
- `manufacturer_approved` fitments render as evidence-backed recommendations.
- Catalog identity is persisted; search pagination has deterministic ordering and cancellation.
- Reproducible Supabase baseline/config/migration chain includes all 663 enabled catalog models.
- Existing-database hardening now repeats baseline-only function upgrades, so fresh install and upgrade receive the same auth conflict handling and deterministic catalog ordering.
- Canonical Wave 14–16 hashes and a 663-ID master manifest are enforced by `check:catalog`.
- CI, 12 core regression/unit tests, all-Edge checks, SQL parser gate and full mobile release script are present.
- Ride duration now excludes pauses and implausible segments, altitude gain is smoothed, and privacy masking also applies to the stored and displayed route line.
- Catalog selection hydrates factory fitments, manual components participate in per-slot default-deny recommendations, and failed cloud saves remain in the editor.
- Road, gravel and MTB use distinct routing profiles; changing route bounds refits the map; primary tablet content uses adaptive max-width containers.

## Verified gates

- `npm run check:release`
- Expo Doctor: 20/20
- iOS and Android Expo exports
- Route portability: Taganrog, Freiburg and Girona, 3/3 green
- SQL hardening migration: parsed locally and executed inside a rolled-back live transaction
- Supabase security advisor: no findings at audit time

## Controlled release gates

- Production database migration history must mark the full baseline as applied only after backup and drift review; only the hardening delta should remain pending.
- Updated `ride-processor` and `route-generator` Edge Functions are not deployed by this source checkpoint.
- Physical device QA remains required for Apple Health, Health Connect, maps, deep links, dark/tablet layouts and native permission prompts.
- Catalog breadth is 663 models / 43 brands, but component/photo/spec depth remains an enrichment backlog and must not be described as complete factory coverage.
- Raw rows missing a canonical category/model-year evidence field are normalized deterministically in the generated baseline, without inventing technical specifications or compatibility.
