## What changed after 0.8.5

### Production migration strategy

A release-engineering gap was found before production rollout: catalog evidence Waves 17–18 are already embedded in the full baseline migration, while the intended existing-production workflow repairs that baseline migration as applied after object-parity review. Without an additional forward migration, those evidence rows would never reach the existing live project.

The fix is a new idempotent migration:

`20260812170000_catalog_enrichment_catchup_waves_17_19.sql`

For fresh databases, the full baseline still creates the complete current state. For the existing production project, the controlled path is:

1. prove baseline object parity and mark the baseline migration applied rather than replaying it blindly;
2. apply `20260811190000_release_hardening.sql`;
3. apply the forward catalog catch-up for Waves 17–19;
4. deploy the reviewed Edge Function delta;
5. run advisors and runtime smoke/RLS/reward-trust checks.

The generated migration set is now **5 files** and backend reproducibility checks require the catch-up migration explicitly.
